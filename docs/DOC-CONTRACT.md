# 文档契约

本文件说明本项目文档的维护规则。规则本身由 `tools/check_docs.cjs` 强制校验，非零退出即视为文档不合格。

## 三条铁律

### 1. 只描述当前状态

README 与 `docs/` 里不写历史轮次、不写「以前是 X，现在是 Y」、不写版本演进日志。读者打开文档，看到的就是这一刻的事实。

演进过程、踩坑记录、废弃方案放 `.scratch/`（不进版本库），或写进 commit message。

### 2. 数字只有一个来源

版本号、自测项数、产物字节数这类**会随代码变化的数值**，只允许出现在一个地方：[FACTS.md](FACTS.md)，由 `node tools/gen_facts.cjs` 实测生成。

手写文档要提这些数字时，引用 FACTS.md，不要抄写。理由是抄写必然漂移：改了代码忘了改文档，文档就变成谎言，而读者无法分辨哪句是真的。

FACTS.md 本身**禁止手改**——它在文件头标注了这一点，任何手改都会在下次生成时被覆盖。

### 3. 结论当场实测

写进文档的每个事实都要有本次运行的证据。查不到就写查不到，不靠记忆补齐。

接口地址、请求头、字段名这类实现细节，必须来自实际抓包或实际跑的请求，不能凭「应该是这样」写下来。

## 文件分工

| 文件 | 谁写 | 内容 |
| --- | --- | --- |
| `README.md` | 手写 | 面向使用者：能导出什么、怎么用、输出格式、隐私 |
| `docs/FACTS.md` | 机器生成 | 所有会变的数字 |
| `docs/DOC-CONTRACT.md` | 手写 | 本文件，文档规则 |

## 校验项

`npm run check` 会做这些检查：

- FACTS.md 与 `.scratch/facts.json` 已生成
- FACTS.md 里的数字与**独立重测**结果一致（不复用生成器的代码，避免同一处写错一起错）
- FACTS.md 标注了「机器生成」「请勿手改」「唯一来源」
- 采集异常段必须是有异常先修，不能带着错误生成
- 自测台当前全绿（`FAIL=0`）
- `dist/` 产物字节与 FACTS 记录一致
- 手写文档里没有抄写受管数值
- 没有历史轮次章节这类废弃写法
- 关键实现约束仍然成立（见下）

## 代码断言

除了文档本身，某些「文档这么说、代码就必须这么做」的约束也被断言化，防止文档与实现脱钩：

- 脚本必须声明 `@match https://connect.ubisoft.com/*`
- 脚本必须保持 `@grant none`（不申请 GM 权限，走页面内 fetch）
- 自测台必须覆盖 401 换票路径

这些断言写在 `facts.config.json` 的 `docs.codeAssertions` 里。

## 收尾流程

改动代码、数据或文档之后：

```bash
npm run build     # 产物与版本校验
npm test          # 自测
npm run facts     # 重新生成 FACTS.md
npm run check     # 文档体检，必须 0 失败
```

四条命令全绿才算改完。不看输出、只口头宣称通过，不算。
